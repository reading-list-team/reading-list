# v3.1 release checklist

This branch starts from the published v3.0.1 source commit `7595ef9270d3f35479f47e77caf9546f52c80d23`. Do not publish it until every gate below is checked with the **actual package** and a disposable Chrome profile. The branch is not a Store submission.

## Do this before Store submission

Use Chrome **test profiles only**. Do not test in your everyday signed-in profile, and do not remove the extension between upgrade steps; removal clears its local data. If `/private/tmp/reading-list-upgrade-check/` is missing, ask for a fresh test kit before continuing.

### 1. Test the combined v3.1 popup

1. In your existing Reading List QA Chrome profile, run `sh /private/tmp/reading-list-upgrade-check/switch.sh candidate` in Terminal. Open `chrome://extensions` and click **Reload** on Reading List. Check version **3.1.0** and ID `lloccabjgblebdmncjndmiibianflabo`.
2. Save three harmless web pages. Close and reopen the popup; all three must remain. Search for one title: the search field should focus as it opens, filter the list, and close with X or Escape.
3. Hover over a row, then use Tab to reach its actions. Edit a title with Enter. Visit that same URL and press + again: the custom title, date, viewed state, and order must stay unchanged, with an “Already saved” message. Cancel another edit with Escape. Copy a URL. Delete a page and use Undo; the page must return.
4. Choose Manual sort. Drag a row to another position, close and reopen the popup, and confirm the new order stayed. Move a row with the drag handle's arrow-key alternative. Switch to Date and Title sorts; dragging must not change saved manual order in those modes.
5. Open the settings sheet. Try System/Light/Dark and the new-tab setting; reopen the popup to confirm they persist. Turn off “Show viewed pages,” open a saved page, and reopen the popup. The page should appear under a collapsed “Viewed (count)” section; expand and collapse it. Open the full settings page. Check that controls fit without clipping.
6. On the settings page, import `/private/tmp/reading-list-upgrade-check/sample-25-pages.json`. Confirm the preview, import, scroll the long list, and search it. Export a backup; import that backup again and confirm existing pages are not duplicated or overwritten.

### 2. Test a clean v3.0.1 upgrade

1. Create **another** Chrome test profile without signing in. Run `sh /private/tmp/reading-list-upgrade-check/switch.sh published`. At `chrome://extensions`, enable Developer mode and **Load unpacked** from `/private/tmp/reading-list-upgrade-check/active`.
2. Check version **3.0.1** and the same extension ID. Save three harmless pages and note their titles.
3. Run `sh /private/tmp/reading-list-upgrade-check/switch.sh candidate`, then click **Reload** on the extension card. Check version **3.1.0**. All three pages must remain with the same titles and no duplicates. Note any permission prompt; an unpacked reload cannot by itself prove what the Store update prompt will do.

### 3. Test full sync storage and rollback

Do this in the new upgrade test profile after step 2. Right-click the v3.1 popup, choose **Inspect**, then open DevTools **Console**. Paste the following test-only filler:

```js
for (let i = 0; i < 100; i++) {
  try {
    await chrome.storage.sync.set({
      [`qa-filler-${i}`]: { padding: 'x'.repeat(1900) }
    });
  } catch (error) {
    console.log('Chrome sync is full after', i, 'test records');
    break;
  }
}
```

1. Save one new page. It must appear with a **saved only on this device** warning. Close and reopen the popup; the page must remain.
2. Run the `switch.sh published` command and click **Reload**. The three original synced pages should be present; the new local-only page will be hidden by old v3.0.1.
3. Run the `switch.sh candidate` command and click **Reload**. The local-only page must return.
4. In the v3.1 popup Console, remove the filler records:

```js
await chrome.storage.sync.remove(
  Object.keys(await chrome.storage.sync.get(null))
    .filter(key => key.startsWith('qa-filler-'))
);
```

`undefined` is the normal result of that removal. Click **Try again** in the popup; the local-only warning should clear or decrease. Export a backup once more.

### 4. Cross-device check

If you have a disposable Google test account, sign two separate Chrome test profiles into it with Chrome Sync enabled and load v3.1 in both. Save on profile A, then check that it appears on B; edit and delete a page and check the change reaches the other profile. Never use your personal Chrome account for this test. If you cannot do this check, report it as **not tested** rather than a pass.

### Send back the result

Report **Pass / Fail / Not tested** for sections 1–4. For a failure, include the exact action, what happened, and a screenshot or DevTools error. Do not upload or publish the Store ZIP during these tests.

## Storage behavior to verify

- Local storage is the primary copy. An accepted local write is a save even when Chrome sync rejects the mirror write. The popup must say when a page is only on this device.
- Migration reads existing URL-keyed `chrome.storage.sync` records, copies valid pages into local storage, and never clears legacy sync keys. Unknown sync keys remain in sync and are included in export.
- v3.1 deletion replaces a synced page with `{url, deletedAt}`. Published v3.0.1 ignores this object because it has no `addedAt`. A failed sync write leaves a local tombstone and displays a warning.
- A missing sync key by itself does not delete a local page. Explicit v3.1 deletion markers remove an unchanged mirrored page. A locally edited page stays visible and is marked local-only when a remote deletion conflicts.
- Export contains the active list plus raw local and sync snapshots. Import accepts v2 raw JSON and v3.1 backups, previews records, merges pages without overwriting existing URLs, and restores settings only when selected.

## Manual test matrix

Use throwaway profiles seeded with copies of data, never a live user's browser profile.

| Case | Pass condition |
| --- | --- |
| Fresh install | Add, search, edit title, drag in Manual sort, move by keyboard, sort by date/title, change theme and open-in-new-tab, mark viewed, expand/collapse Viewed, delete/Undo, and reopen all work. Saving an existing URL again must say “Already saved” without changing its edited title, date, viewed state, or order. |
| Redesigned popup | At the real popup size, check hover and keyboard row actions, search focus/X/Escape, sort menu, settings sheet, empty/loading states, long-list scrolling, local-only notice/Retry, and readable error messages. No action should disappear behind the footer. |
| Options page | Open it from the settings sheet; check settings persistence, backup export, import preview, invalid-file error, and the local-only recovery explanation. |
| v3.0.1 upgrade | Page count, URL, title, and dates match before/after; old sync records remain; export includes both storage snapshots. |
| v2-shaped data | `viewed`, `index`, unknown item fields, dark theme, sort preference, and `openNewTab` survive migration and title edits. Untitled pages remain visible using the URL as fallback. |
| Sync quota full and per-item rejection | Add and edit still save locally; popup shows local-only state; export includes the page. Retry after freeing space syncs eligible items. |
| Local storage write failure | No success message or UI mutation; original list remains visible. |
| Two v3.1 devices | In-quota add/edit/settings changes arrive in the other popup. Explicit deletion marker removes an unchanged mirrored page. Concurrent edits remain recoverable in backup and are not silently overwritten by retry. |
| Mixed v3.0.1/v3.1 devices | v3.0.1 can read mirrored items and ignores v3.1 deletion markers. Its own deletions use bare key removal, so v3.1 conservatively keeps local copies; document this mixed-version limit. |
| Offline/restart | Local saves survive popup/browser restart and remain marked local-only until Chrome accepts sync. No page disappears because sync returned an empty snapshot. |
| Export/import | Download v3.1 backup; import into a fresh profile; compare all page fields and settings. Import v2 raw export. Malformed JSON and invalid records produce a clear message without altering existing pages. |
| Permission/update prompt | Install published v3.0.1 in a disposable profile, then update with the candidate package under the same extension ID; record any prompt caused by `unlimitedStorage`. |
| Rollback rehearsal | Update a seeded profile, create a local-only overflow page, roll back to v3.0.1, then restore v3.1. Old v3.0.1 cannot show local-only overflow, but the local copy and backup must remain recoverable when v3.1 returns. |

## Rollout

1. Submit the reviewed package with deferred publishing. Confirm the Store listing's privacy statements still match the actual storage behavior.
2. If Chrome Web Store percentage rollout is available, publish to 1%, then 5%, 20%, 50%, and 100%, with a soak and go/no-go review at each step. New installs may receive the newest version during partial rollout.
3. Watch support reports for missing pages, import failures, unexpected permission prompts, and local-only/sync failures. Pause immediately for any credible data-loss report.
4. If needed, use Store rollback to the prior published package. Do not clear either storage area. A rollback hides local-only overflow from old v3.0.1, so preserve the local data and follow with a corrected v3.1 package.
