# v3.1 release checklist

This branch starts from the published v3.0.1 source commit `7595ef9270d3f35479f47e77caf9546f52c80d23`. Do not publish it until every gate below is checked with the **actual package** and a disposable Chrome profile. The branch is not a Store submission.

## Storage behavior to verify

- Local storage is the primary copy. An accepted local write is a save even when Chrome sync rejects the mirror write. The popup must say when a page is only on this device.
- Migration reads existing URL-keyed `chrome.storage.sync` records, copies valid pages into local storage, and never clears legacy sync keys. Unknown sync keys remain in sync and are included in export.
- v3.1 deletion replaces a synced page with `{url, deletedAt}`. Published v3.0.1 ignores this object because it has no `addedAt`. A failed sync write leaves a local tombstone and displays a warning.
- A missing sync key by itself does not delete a local page. Explicit v3.1 deletion markers remove an unchanged mirrored page. A locally edited page stays visible and is marked local-only when a remote deletion conflicts.
- Export contains the active list plus raw local and sync snapshots. Import accepts v2 raw JSON and v3.1 backups, previews records, merges pages without overwriting existing URLs, and restores settings only when selected.

## Automated gate

- `npm ci`
- `npm run build`
- `npm test`
- `git diff --check`
- Inspect `build/manifest.json`: same extension identity, version set to 3.1.0 at release, and only the planned `unlimitedStorage` permission added.

## Manual test matrix

Use throwaway profiles seeded with copies of data, never a live user's browser profile.

| Case | Pass condition |
| --- | --- |
| Fresh install | Add, search, edit title, drag in Manual sort, move by keyboard, sort by date/title, change theme and open-in-new-tab, mark viewed, show unread, delete/Undo, and reopen all work. |
| Redesigned popup | At the real popup size, check hover and keyboard row actions, search focus/X/Escape, sort menu, settings sheet, empty/loading states, long-list scrolling, local-only notice/Retry, and readable error messages. No action should disappear behind the footer. |
| Options page | Open it from the settings sheet; check settings persistence, backup export, import preview, invalid-file error, and the local-only recovery explanation. |
| v3.0.1 upgrade | Page count, URL, title, and dates match before/after; old sync records remain; export includes both storage snapshots. |
| v2-shaped data | `viewed`, `index`, unknown item fields, dark theme, sort preference, and `openNewTab` survive migration and title edits. Untitled pages remain visible using the URL as fallback. |
| Sync quota full and per-item rejection | Add and edit still save locally; popup shows local-only state; export includes the page. Retry after freeing space syncs eligible items. |
| Local storage write failure | No success message or UI mutation; original list remains visible. |
| Two v3.1 devices | In-quota add/edit/settings changes arrive in the other popup. Explicit deletion marker removes an unchanged mirrored page. Concurrent edits remain recoverable in backup and are not silently overwritten by retry. |
| Mixed v3.0.1/v3.1 devices | v3.0.1 can read mirrored items and ignores v3.1 deletion markers. Its own deletions use bare key removal, so v3.1 conservatively keeps local copies; document this mixed-version limit. |
| Offline/restart | Local saves survive popup/browser restart and remain marked local-only until Chrome accepts sync. No page disappears because sync returned an empty snapshot. |
| Export/import | Download v3.1 backup; import into a fresh profile; compare all page fields and settings. Import v2 raw export. Malformed JSON and invalid records produce a clear message without altering existing pages. |
| Permission/update prompt | Install published v3.0.1 in a disposable profile, then update with the candidate package under the same extension ID; record any prompt caused by `unlimitedStorage`. |
| Rollback rehearsal | Update a seeded profile, create a local-only overflow page, roll back to v3.0.1, then restore v3.1. Old v3.0.1 cannot show local-only overflow, but the local copy and backup must remain recoverable when v3.1 returns. |

## Rollout

1. Submit the reviewed package with deferred publishing. Confirm the Store listing's privacy statements still match the actual storage behavior.
2. If Chrome Web Store percentage rollout is available, publish to 1%, then 5%, 20%, 50%, and 100%, with a soak and go/no-go review at each step. New installs may receive the newest version during partial rollout.
3. Watch support reports for missing pages, import failures, unexpected permission prompts, and local-only/sync failures. Pause immediately for any credible data-loss report.
4. If needed, use Store rollback to the prior published package. Do not clear either storage area. A rollback hides local-only overflow from old v3.0.1, so preserve the local data and follow with a corrected v3.1 package.
